# Plan: "Jahan" — an open-source real-world society simulator

## 1. Context

The user wants an open-source, non-game simulator of human society: thousands of agents with research-grounded demographic, psychological, physical, economic, linguistic and informational profiles, living in different countries and time zones, embedded in family/relative/colleague/friend circles, talking daily and exchanging good and bad information through trust-weighted relationships, sleeping on local time, marrying, having children (new agents), divorcing, dying, travelling. A user can browse agents, open one and see the world from its perspective, inject a scenario by free-text prompt ("launch product X", "the dollar rises", "gold +1%/day for a week then −10%", "Iran–US war intensifies") scoped to one agent, a group or the whole world, watch effects emerge, and reset the world to any checkpoint before a prompt.

The first prompt of the session (2026-10-12) plus the mid-turn addition (sleep by time zone, non-unique culturally appropriate names, agent browser + perspective prompts) define the scope. This plan must stay aligned with them.

**Addition of 2026-10-13 (user):** (a) every agent has a different **public visibility**: a US president's statements reach vastly more people than an unemployed person's; (b) **real people can act as agents**: a user can create a new agent or take control of an existing one (e.g. the US president), interact with other agents mainly by giving them information, and thereby affect outcomes.

## 3. Architecture (decisions)

1. **Hybrid cognition.** Numeric engine (time budgets, awake masks, contact sampling, trust-weighted diffusion, utility decisions, life-event hazards) runs every agent every day with zero network/LLM I/O. The LLM is used ONLY for: (a) free-text prompt → structured `Scenario`/`Query` (with clarifying questions), (b) headline classification during ingest (batched, or local embeddings), (c) persona interviews of sampled agents, (d) rendering readable transcripts from structured exchange records on demand, (e) optional report prose, (f) choosing typed `Action`s for uncontrolled notable agents on salient days, (g) extracting InfoItems from human players' free text and writing in-character replies to them. The LLM never mutates world state directly; every state change is a typed event produced by the engine, and the size of any effect is computed by the engine. This is the anti-"narration" guarantee.
2. **Struct-of-arrays state.** All agent/edge/item state lives in numpy column arrays (a generic growable `SoATable`), not 10k Python objects. Tables are preallocated with headroom (agents 1.5× initial, edges 1.3×) and grow by amortized doubling only when exhausted; births append into free slots; deaths set `alive=False` (periodic compaction keeps uids stable); ids are never reused. Pydantic only for config, country YAML, registry, Scenario/Query specs, reports. All hot phases are whole-array numpy ops; if the bench gate fails, the escape hatches are Numba kernels first, Rust (PyO3) second.
3. **Stateless hash RNG.** `u01(seed, stream, day, keys, k)` = splitmix64 over `(seed, stream, day, key, k)` in numpy `uint64`. Order-independent, per-agent/per-edge draws, no RNG state in snapshots, and common random numbers across baseline/treated branches for low-variance paired differences. **Canonical key encoding (Copilot fix):** fields are fixed-width unsigned integers `seed:u64, stream:u16, day:u32, k:u32, key:u64`; `base = mix(mix(seed ^ DOMAIN_TAG) ^ ((stream << 48) | day)) ^ (k · GOLDEN)`, then per element `mix(base ^ mix(key))`, where `mix` is the splitmix64 finalizer and `DOMAIN_TAG` is a fixed constant per RNG family (simulation vs generation). Stream ids are a frozen registry in `rng.py`. `tests/unit/test_rng_vectors.py` pins known output vectors that CI checks on Windows and Linux.
4. **Day tick + 24-bit availability masks.** Tick = 1 simulated day (UTC). Each agent has `tz_offset_min` and a chronotype; per day the engine computes a `uint32` awake/free-hours bitmask from local time zone, sleep window (default 23:00–07:00 local ± chronotype, shifted for shift workers), work/school hours and day-of-week. Media exposure requires the item's release hour ∈ agent's awake mask; contacts require overlapping free hours of both agents (cross-time-zone contact only in overlap). Known limitation (agy): max one social hop per day; mitigation path in M2 is 4 six-hour sub-phases for diffusion only, not a 24× hourly loop.
5. **Record/replay for everything non-deterministic.** Web fetches, LLM outputs and human players' inputs are recorded inside the run directory and become logged events. Reset + re-run consumes the recordings, never the network. "Live" means live **ingest**: the ingest command fetches real content once into simulated channels, not per-agent browsing; the simulation loop itself is pure. **Replay manifest (Copilot fix):** `recordings/manifest.parquet` maps a `request_key` to the response. The key is the sha256 of canonical JSON `{kind: web|llm|human, sim_day, purpose, url | (provider, model, model_version, params, messages) | (session_id, seq)}`; the row stores `response_hash`, `fetched_at_utc`, `status`, `cost_usd`. In replay mode a missing key **fails closed** with an error naming the request; new calls are allowed only when the run moves forward past the last recorded day.
6. **Deterministic re-run, not log replay.** Because the core is deterministic given (snapshot, params, recordings), the event log is an output. Reset = load pre-prompt snapshot + truncate logs at chunk boundaries + re-run.
7. **Two user verbs.** `inject` changes the world (Scenario → timeline of WorldEvents). `ask` queries perspectives without changing the main timeline (scope = agent | group | world; optionally `--with-scenario` to branch, run, then interview inside the branch).
8. **Counterfactual reporting.** Every injected scenario is evaluated as K seeds × {baseline, treated} from the pre-prompt snapshot; primary results are paired differences with min/max and sd bands, plus breakdowns and sampled narratives.
9. **One Action interface for humans and public figures.** Human-controlled agents and LLM-driven notable agents submit the same typed `Action`s (`SayTo`, `PostPublic`, `Decide`, `PolicyAction`). The engine validates each against the agent's role permissions, time-of-day availability and circle, then applies it as events. A possession session is naturally the "treated" branch and autopilot is the baseline, so "did my intervention matter?" uses the existing `experiment` command.
10. **Visibility is a first-class attribute.** Every agent has a log-scale `visibility` (potential audience). It sets the reach of the agent's public statements, how strongly media pick them up, and how many agents hold a parasocial trust relation to them.

## 5. Data model (Milestone 1 + extension points)

**Agent table** (SoA columns):
- identity: `id` i64, `alive` bool, `country` i16, `region` i16 (urban/rural in M1), `household_id` i32, `first_name_id` i32, `last_name_id` i32 (indexes into per-country name tables; names deliberately non-unique), `pop_weight` f32
- demographics: `sex` i8, `birth_day` i32, `ethnicity` i16, `religion` i16, `marital` i8, `spouse_id` i64, `mother_id`/`father_id` i64, `n_children` i8
- body: `health` f32, `vision_impaired` i8, `hearing_impaired` i8, `strength_z` f32, `attractiveness_z` f32
- mind: `big5` f32(5), `risk_tolerance` f32, `values` f32(6) = (self, money, culture, freedom, family, security), `wants_kids` f32, `interests` f32(12 topics), `discernment` f32, `honesty` f32 (derived from agreeableness/conscientiousness + values; drives distortion of shared information, i.e. "good/bad advice"), `aggression` f32 (bully trait: low agreeableness × high extraversion; imposes a trust-prior penalty on repeated contacts)
- upbringing (from the first prompt's "childhood / grow-up conditions"): `childhood_ses` f32 (income quintile of household at age 0–15), `parent_edu_max` i8, `raised_by` i8 {two-parent, single, other}; for agents generated at world creation these are sampled conditional on country, cohort and current SES (intergenerational-mobility priors, `confidence: low`); for agents born in-sim they are set from the actual household at birth and updated at age 15
- capital: `education` i8 (ISCED 0–8), `field` i8, `emp_status` i8, `occupation` i8 (ISCO-08 major group), `workplace_id` i32, `income_month` f32 (local currency), `wealth` f32
- information: `info_tier` i8 {0 minimal, 1 major news, 2 well-informed, 3 specialist}, `internet` bool, `focus_topic` i8
- language: `lang` i16(3), `lang_prof` f32(3)
- time: `tz_offset_min` i16, `chronotype` f32, `work_shift` i8 {day, evening, night, none}
- social: `global_rep` f32, `last_outcome_day` i32
- public role: `visibility` f32 (log10 of potential audience: ~1 household, ~2.5 community figure such as a teacher or imam, ~4 local official or journalist, ~6 national figure, ~8+ head of a large state), `is_notable` bool, `role_id` i16 (−1 none), `controlled_by` i32 (−1 autopilot, else session id). Ordinary agents draw visibility from a heavy-tailed distribution conditional on occupation, extraversion, education and internet use, capped at community level; notables take it from the roster.

**Edge table** (directed, trust is directional): `uid` i64 (stable RNG key), `src`, `dst`, `kind` i8 {household, kin, colleague, classmate, friend, acquaintance, cross_border}, `strength` f32, `alpha` f32, `beta` f32 (Beta-posterior pseudo-counts), `prior_alpha`/`prior_beta` f32 (reputation + homophily + attractiveness halo), `created_day`, `last_contact_day`, `active` bool. Effective trust = `(alpha + w·prior_alpha) / (alpha + beta + w·(prior_alpha + prior_beta))` where halo weight `w` fades with `n_outcomes`; negative outcomes update `beta` with weight 2.5× (negativity bias). Recency: evidence decays **toward the edge's prior, never toward zero**, and only lazily when a new outcome arrives: `alpha = prior_alpha + (alpha − prior_alpha)·λ^(Δdays)` (same for beta), so dormant ties keep their baseline trust instead of freezing diffusion (agy's final-review correction, adopted).

**Notable agents** (~10–15 per country, ~100 in M1): loaded from `data/notables/{CC}.yaml`, inserted as full agents with `is_notable = True`, `pop_weight = 0` (they are excluded from population aggregates, like human-created agents), an office, a stance vector in the same basis as `values`, and an approval prior (from published approval polls where available, else `placeholder`). They are excluded from population marginal tests. **Parasocial trust** is a dense matrix `ptrust_alpha/ptrust_beta` of shape agents × notables (10k × 128 × 2 floats ≈ 10 MB). Its columns are fixed at world creation: the roster plus 16 reserved columns for `create-agent --notable`. Ordinary agents who go viral never get a column; receivers outside their circle judge them with a prior from `global_rep` (agy). Its prior comes from value alignment with the notable's stance, approval prior, info tier, and a foreign-leader discount; it updates with the same Beta rule as edges when acting on the notable's statements turns out well or badly.

**Household / Workplace / MediaChannel / Country** as in the internal draft; `Country` adds `time_zones[{offset_min, share}]`, `currency`, `fx_to_usd_initial`, `name_table`, `feeds`.

**InfoItem table**: `id`, `created_day`, `release_utc_hour` i8, `topic` i8, `valence` f32, `truth` f32, `salience` f32, `credibility` f32, `origin_kind` i8 {agent, channel, web, user_feed, scenario, macro, synthetic, notable, human}, `origin_id`, `entity_id` (product id or −1), `lang` i16, `countries` bitmask, `active_until`, `content_hash` (links to recorded raw text).

**Two item classes (required once live ingest exists; ~1000 headlines/day would otherwise blow any dense cap and the perf budget):**
- **Tracked items** get a belief column and word-of-mouth diffusion: scenario/product items, user-fed events, macro auto-items, and the top web items by salience × relevance to active scenarios. Cap on concurrently live tracked items: `MAX_TRACKED = 32 per country, 256 total` (dense matrices `aware` u8, `belief` f32, `heard_from` i64, `heard_day` i32, `adopted_day` i32, `satisfaction` f32 over a recycled column pool; a column is freed at `active_until`). Only tracked candidates get Haiku valence/truth scoring, which bounds classification cost.
- **Ambient items** (everything else from ingest) are media-exposure only: they update per-agent per-topic `topic_sentiment` f32(12) and `topic_awareness` f32(12) counters, no per-item belief, no diffusion. Sparse per-item beliefs remain an M2 option.

**Macro state** (per country per day): `fx_to_usd`, `inflation_m`, `sentiment`; global series e.g. `gold_usd`. Driven by `MacroPath` events; each day with |Δ| above a threshold auto-emits an InfoItem ("dollar up 3% vs rial") with salience ∝ |Δ|.

**Events** (Parquet; fixed typed columns `day, seq, kind, agent, other, item, value, country, detail`): `BORN, DIED, MARRIED, DIVORCED, JOB_CHANGED, STATUS_CHANGED, INFO_EXPOSED (first exposure), ADOPTED, OUTCOME_REALIZED, SCENARIO_INJECTED, ITEM_CREATED, MACRO_UPDATE, WEB_INGESTED, USER_FEED, INTERVIEW (content hash of LLM output), AGENT_CREATED, POSSESSED, RELEASED, HUMAN_ACTION, NOTABLE_ACTION, ACTION_REJECTED (permission or availability failure, with reason), ACTION_SKIPPED (precondition failed during counterfactual replay), AUTOPILOT_TURN, SNAPSHOT`. Per-contact and per-trust-nudge events are NOT logged (aggregated in metrics).

**Scenario / Query specs** (Pydantic, `scenario/spec.py`):

## 6. Information environment (live web per tier, reproducible)

- `jahan ingest --run R --days N` (network I/O only here): for each country/language fetch Google News RSS with locale params and the curated OPML outlets; store raw items (title, snippet, url, published_utc, lang, source) in `runs/R/corpus/*.parquet` keyed by content hash; `classify.py` assigns topic (local CPU embeddings via `fastembed` with `sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2`, 384-d, 50+ languages, Apache-2.0; Qdrant publishes a quantized ONNX port loadable through fastembed's `TextEmbedding` — confirm with `TextEmbedding.list_supported_models()` at implementation; fallback is `sentence-transformers` on CPU) and, for items above a relevance threshold, valence/truth-claims via batched Haiku calls (budgeted). Fetching is defensive: per-feed HTTP caching (ETag/Last-Modified), exponential backoff on 429/5xx, per-host rate limits, and a documented fallback to `data/feeds/fixtures/` when a feed is geo-blocked or empty (the world keeps running; the gap is logged as a `WEB_INGEST_FAILED` event). Items become `InfoItem`s with `origin_kind=web`, attached to channels by tier: tier 1 → top 2–3 national outlets; tier 2 → all outlets + international; tier 3 → specialist feeds (e.g. arXiv category RSS, trade press) for their `focus_topic`.
- Historical back-fill at world creation: last 30 days from the same feeds (RSS depth permitting). GDELT is NOT used in M1 (DOC API window/limits conflicting in sources; agy advises against); listed as an M2 option for historical calibration runs.
- Future days beyond real "now": when `run` crosses the real date, the CLI asks: "Simulated days D1–D2 have no real news. Feed events? [text | file | skip]". Free text → `scenario/feed.py` → LLM (Sonnet) → list of timed `NewsEvent`/`MacroPath` → printed → confirmed → logged as `USER_FEED` and injected on schedule. Non-interactive: `jahan feed --file events.md`. Optional low-volume synthetic background headlines (Haiku, ~5/country/day, labelled `synthetic`) behind a config flag, default OFF per the user's answer.
- Sleep rule (reworded per Copilot): an item released at UTC hour h reaches an agent only if bit h, converted to local time, is in the agent's awake mask; otherwise it becomes eligible at the agent's **next awake hour, which may be later the same local day** (released 02:00 local, seen at 07:00 local) or the next local day. Time-zone offsets are kept in minutes; masks are hourly bins, so half-hour and 45-minute zones (India +5:30, Iran +3:30, Nepal +5:45) round to the bin that contains the local half-hour start, documented as a coarse approximation. Unit tests cover a 02:00 UTC release, India and Iran offsets, and a sleep window crossing midnight.

## 7. Synthetic population + data registry

Method: conditional-chain sampling per country (IPF only in M2 if microdata is added), in fixed order: (sex, age) → region → ethnicity, religion → languages (L1 by ethnicity; L2/L3 with P(multilingual | education)) → education | age, sex → employment status | age, sex, education → occupation | education → income | occupation (lognormal) → Big Five ~ N(country mean, sd) → risk tolerance, values (WVS profile + noise), wants_kids → interests → info tier | education, internet | age → vision/hearing | age → attractiveness, health, strength → time zone | region share, chronotype → name | sex, ethnicity (weighted). Households assembled to match household-size distribution and married-adult share; workplaces/schools; social graph: household (complete), kin clans, colleagues/classmates, friends with homophily (age/education/interests, language-gated), acquaintances via small-world rewiring; cross-border ties (M1: minimal, proportional to UN migrant-stock origin→destination shares and gated by shared language; M2: gravity model with trade/tourism).

`data/registry.yaml` entry schema: `id, country, variable, source, url, year, retrieved, license, confidence{high|medium|low|placeholder}, notes`. `jahan validate-data` fails on missing ids, shares not summing to 1, or (with `--strict`) any `placeholder`. `scripts/gen_data_docs.py` renders `docs/data-sources.md`.

## 8. Daily tick, time travel, scenario engine, queries

**Tick order** (`sim/tick.py: run_day`, canonical, part of the reproducibility contract):
0 inject scheduled WorldEvents (scenario, user feed, macro step → MACRO_UPDATE + auto InfoItems) → 1 availability masks + time budgets (sleep, work, family time grows with marriage/kids) → 2 media exposure (channel reach × tier × language × awake mask × salience) → 3 contact sampling per edge (strength × free-hour overlap) → 4 diffusion (share prob from conviction/extraversion/interest; accept prob from trust, openness, bounded-confidence distance; belief pulled toward truth by discernment) → 5 decisions (logistic adoption hazard over belief, affordability incl. fx, peer adoption, risk tolerance, value fit) and realized outcomes after a lag → 6 trust updates (Beta posterior, negativity bias, recency decay, halo fade) → 7 life events (death, birth → new agent with inherited attributes and name, marriage via deterministic sorted matching within country, divorce, job change, age transitions) → 8 metrics → 9 log flush, periodic snapshot.

**Run directory**: `config.json params.json meta.json prompts.json(ledger) scenarios/ corpus/ recordings/(llm + web, hash-keyed) snapshots/day_xxxxx.npz(+json) + pre_prompt_<id>.npz events/*.parquet metrics/*.parquet experiments/<prompt>/seed_s/{baseline,treated} reports/`.
**Reset**: `jahan reset --before-prompt N` loads `pre_prompt_N`, deletes chunks with start day ≥ that day (chunk boundaries align with snapshots and pre-prompt snapshots force a boundary), drops ledger entries ≥ N, records `reset_history`. Recordings are kept (hash-keyed) so re-runs reuse them.

**Scenario flow**: `jahan inject --run R "<prompt>"` → `LLMScenarioParser` (Sonnet, JSON schema from `Scenario.model_json_schema()`, retry on validation error; if the prompt is ambiguous it returns `clarifying_questions` which the CLI asks the user) → printed spec → `--confirm` → pre-prompt snapshot → ledger → scheduled. `jahan experiment --prompt N --seeds K --horizon H` runs baseline/treated per seed with common random numbers (ProcessPool, 4 workers; Windows uses `spawn`, so workers receive only the snapshot path and seed and load state from disk themselves, nothing large is pickled). `jahan report --prompt N` → paired differences, curves at 7/30/90/180 days, breakdowns (country, income quintile, info tier, age, sex, urban/rural), word-of-mouth vs media share, top influencers, trust deltas, template narratives; optional LLM prose.

**Queries / perspective**: `jahan agents list --filter "country=='IRN' and age>30"`, `jahan agent show <id>` (profile card, name, circle with trust values, awake schedule, beliefs, exposure log, timeline). `jahan ask --scope agent:<id>|group:<filter>|world "<question>" [--with-scenario file|prompt]`: builds a closed-world **mind snapshot** per sampled agent (profile, numeric beliefs, items actually received during awake hours in a language they speak, top ties and their stances) and interviews via Haiku with strict instructions to answer only from listed knowledge; a pre-flight check returns a deterministic "not exposed" template with zero tokens when the agent never received the relevant item; group answers are aggregated (counts + quotes); world scope runs the counterfactual experiment first. All LLM outputs recorded + logged as `INTERVIEW`.

**Transcripts without logging 500k contacts/day:** per-contact records are not stored (§5). Because the core is deterministic, `jahan transcript <agent> --day D` loads the nearest snapshot ≤ D, re-simulates to D with `trace_agents={id}` (the tick captures only that agent's contacts, items exchanged, shared-belief distortions and trust deltas into a small trace table), then renders the trace into a readable conversation (template first; Haiku rendering optional, recorded). Cost ≤ `snapshot_every` days of re-sim (seconds). A determinism test asserts the traced re-run reproduces the original aggregates for that day.

**Good and bad advice (first prompt):** in diffusion the shared belief is distorted toward the sharer's own interest or exaggerated with probability `1 − honesty`; receivers' later `OUTCOME_REALIZED` then penalises the sharer's trust via the Beta update, so dishonest or wrong agents lose trust over time and honest well-informed agents gain it. `aggression` lowers the trust prior others hold toward the agent after repeated contact (bully dynamic) and raises conflict-type exchanges in transcripts.

**Public visibility and notable agents:**
- A `PostPublic` by any agent creates an InfoItem with `origin_kind = notable | agent | human`. Reach is set by visibility: circle (always), community (agents in the same region, probability scaled to audience ÷ represented regional population), national (national channels carry it; agents exposed per channel reach × tier × awake mask), global (foreign channels carry it after a one-day translation lag, gated by language). The requested audience is capped by the actor's visibility.
- Acceptance of a notable's item uses parasocial trust, not edge trust; ordinary agents then pass it on by word of mouth with their own edge trust, so a president's claim is filtered by partisanship and circles.
- Virality: when an ordinary agent's item is accepted by more than a threshold share of its community, the agent's visibility rises (decays back over weeks). Scandal: a large negative outcome on a notable's claim lowers approval and parasocial trust broadly.
- Policy: a notable's `PolicyAction` (e.g. president imposes tariffs, central bank changes rate, CEO cuts a price, anchor emphasises a topic) is checked against `data/roles.yaml` and converted by the engine into `MacroPath`, `NewsEvent`, product-price or channel-salience changes using registry-backed elasticities (`confidence: low` in M1). A president cannot set interest rates; that returns `ACTION_REJECTED`.
- **Real public figures (user decision: real names by default):** each roster entry has `office`, `holder_name`, `as_of` date, `source_url`, documented public stances with sources, and an approval prior with source. The world start date selects the holder in office on that date. Current office holders must be verified by web lookup when the rosters are written, because model knowledge may be out of date. Every piece of text the LLM generates for a real person (statements, replies, transcripts, report quotes) carries a visible `[simulated]` label in the CLI, reports and exports, and the README states that statements are simulated and not real quotes. Persona prompts for real people are grounded only on their sourced public stances. Elections and succession are not modelled in M1, so the holder stays fixed for the run unless a scenario or the user changes it. A config option `notables.names: real | office` lets users switch to office-only personas.
- **Personas as close as possible to the real person (user request 2026-10-13, covers heads of state, CEOs such as Elon Musk, and other key opinion leaders):** each roster entry carries a sourced persona profile: role(s) and organisations; audience size per platform (drives `visibility`); documented stances per topic as a position in [−1, 1] with a summary and a source URL; values vector and risk tolerance derived from those stances and documented decisions; communication profile (platforms used, posting frequency, languages, documented rhetorical style such as "posts many short replies on X"); approval or favourability polls with source; and a short neutral persona brief. The LLM prompt for a notable is grounded only on this profile plus the items the notable was exposed to in the world. Rules: every stance and style claim needs a source URL, or the validator rejects it; no private or personal data beyond public roles and public statements; no personality diagnoses (Big Five for real people is inferred only from documented public behaviour and marked `confidence: low`); generated text stays labelled `[simulated]`. Tooling: `jahan notables draft --country USA --name "<person>"` (1c) fetches public sources through the ingest layer (encyclopedia page, recent news, official sites), has the LLM draft the profile with a citation for every field, and writes it for human review; `jahan validate-data` checks citations, `as_of` dates and that the person still holds the role on the world start date. Roles, ownerships and office holders must be verified by web lookup when rosters are written, because model knowledge may be out of date.
- **Notable autonomy (user decision: LLM on salient days):** a notable gets a decision turn only when a trigger fires: a tracked item relevant to its role passes an awareness threshold in its country, a macro variable moves past a threshold, it is named in a human or notable statement, or a scheduled role event occurs (e.g. central-bank meeting days in `data/roles.yaml`). One Haiku call per turn receives the notable's mind snapshot, its permitted actions and the `Action` JSON schema, and returns zero to two actions or "no action". The engine validates and applies them. Caps: at most two turns per notable per simulated week, **a world-wide ceiling of 20 notable turns per simulated week** (configurable; when more triggers fire, the highest-salience ones win, ties broken by notable id), and a per-role share of the run's USD cap (default 30% for notable autonomy). When a cap is reached notables stop acting and the report says so. Cost per turn is estimated by `budget.py` from the pricing table and shown before a run; agy's rough estimate of $15–40 for 800 turns is unverified, and the global ceiling keeps the worst case well below that. All outputs are recorded in the manifest, so resets replay them exactly.

**Human players (create or take control of agents):**
- `jahan create-agent --run R --country IRN [--profile file | --describe "free text"] [--notable]` builds a new agent: free text goes through the LLM into a validated profile, missing fields are sampled from the country's distributions, and a local wiring kernel (the `graph_gen` homophily rules applied to one agent) gives it a household and circle. It uses the table's preallocated headroom, so no array is reallocated mid-run. Created agents have `pop_weight = 0` and are excluded from population aggregates (agy). `--notable` assigns one of 16 reserved parasocial-trust columns. A pre-creation snapshot is written first, so it is resettable like a prompt.
- `jahan possess --run R --agent <id>` takes control of any agent, including notables; `jahan release` returns it to autopilot. While controlled, the engine skips that agent's autonomous sharing and decisions; physical constraints still apply (the human cannot reach contacts who are asleep; messages queue until the recipient's next awake hour).
- Giving information: `jahan say --to <id> "text"` and `jahan post --audience national "text"`. The text goes through the LLM to extract claims as InfoItems (topic, valence, salience; truth is taken from world ground truth when the claim concerns a simulated entity, otherwise marked unverifiable and excluded from outcome-based trust updates). The recipient accepts or rejects through the normal trust rule, and replies in character through the persona path, so the human gets a real conversation grounded in the recipient's state.
- Every human action is recorded with session id, sequence, sim day and UTC hour, and logged as `HUMAN_ACTION`. Reset before an action removes its effects; replay re-applies recorded actions at the same time.
- **Pacing (user decision: turn-based; quantized to the daily tick per agy):** turns happen at **day boundaries only**, so the vectorized one-day tick is never split. `jahan play --run R --days N` runs a day, then prints the controlled agent's briefing for that day: what it was exposed to, messages received, replies to its earlier messages, macro changes and notable statements. The user enters actions for the coming day, each with an intended local hour (default: the agent's first awake hour). During the next `run_day`, phase 0 applies them in their hour bins using the same availability masks as everything else: a `SayTo` lands if the recipient is awake in that bin, otherwise at the recipient's next awake bin, which may be the following day. `next` continues. `--timeout S` puts the agent on autopilot for that day if nothing is entered; what gets recorded is the outcome (an `AUTOPILOT_TURN` event for day D), never the wall-clock time, so replays stay deterministic. `--auto N` skips N days. A non-interactive `run` treats possessed agents as autopilot unless actions are queued. A running cost meter shows LLM spend against the run cap.
- **Free text cannot set effect sizes (agy, anti-narration):** for human and notable text the LLM extracts only topic, referenced entities, the claim, and a stance quantized to five levels {−1, −0.5, 0, +0.5, +1}. Salience is computed by the engine from the actor's visibility and requested audience, and credibility comes from receivers' trust in the actor. Writing a claim more emphatically therefore cannot make it spread further; a test asserts that a mild and an extreme phrasing of the same claim get identical salience.
- **Replies are bounded (agy):** in-character persona replies are generated only for one-to-one `SayTo`. A `PostPublic` is evaluated purely by numeric diffusion; the next briefing shows aggregate reactions plus at most three sampled quotes, which are budgeted and recorded.
- **Counterfactual replay of sessions (agy):** when `experiment` replays a recorded session on other seeds, an action whose preconditions fail there (target dead, asleep, no longer a contact) is logged as `ACTION_SKIPPED` and the run continues.
- **Multiplayer (user decision: M2):** M1 is single-user; one person may possess several agents and `play` cycles through them. M2 adds a FastAPI server with accounts, lockstep turns across players (the world waits for all active players or their timeouts), per-player budgets and rate limits, and a moderation hook on free text. The `Action` and session-recording formats are designed now so M2 adds transport, not new semantics.

**LLM layer**: `LLMProvider` Protocol with `ScriptedProvider` (deterministic, for tests), `AnthropicProvider` (default; roles: scenario_parser=`claude-sonnet-5-5`, classifier/persona/transcript=`claude-haiku-5-5`; both are config values in `configs/m1.yaml`, and `jahan doctor` validates the configured IDs with a 1-token call and prints the account's available models on failure — agy believes these IDs are hypothetical; this session's environment lists them as the current Claude 5 family IDs, so they are the default but trivially overridable), `OpenAICompatProvider` (base_url + model + key). `budget.py` enforces a per-run USD cap from a pricing table and a per-role token cap; `cache.py` content-hash cache in `recordings/`; `guard.py` global call counter + `forbid_llm()` used by core tests.

## 10. Verification

- **Unit** (`tests/unit`): rng (determinism, stream independence), soa (grow/append/compact keep uids), sampler, availability masks (sleep window across midnight, DST ignored in M1, 02:00 UTC release test), each tick phase on a 50-agent hand-built world, trust posterior (negativity bias, halo fade, decay), lifeevents (dead agents never act; births link households/names), snapshot round-trip, eventlog truncate+hash, spec validation, inject, report math, scope filter parser, persona pre-flight (zero tokens when unexposed).
- **Property** (Hypothesis): generated marginals within tolerance of the registry per country (age ±2 pp, sex ±1 pp, education ±3 pp, employment ±3 pp, language ±3 pp, mean household size ±0.3, married-adult share ±3 pp, internet ±3 pp); u01 uniformity; hazard round-trips; one simulated year reproduces births/deaths/marriages/divorces per 1000 within ±25% (3 seeds, `slow`).
- **Determinism**: two subprocess runs with the same config → identical event-log sha256 and snapshot arrays; reset-then-run equals a fresh no-prompt run; traced re-run for `transcript` reproduces that day's aggregates; `PYTHONHASHSEED`-varied twin run; no-LLM guard (`call_count == 0` after the core demo) + static import test.
- **Item classes**: ingest fixture with 2000 headlines/day keeps live tracked items ≤ cap, ambient items never allocate belief columns, and bench stays within budget with ingest enabled.
- **Replay manifest**: deleting one recording and re-running in replay mode fails closed with the request named; forward runs append new rows; RNG known-vector test passes on Windows and Linux.
- **Weighting**: proportional-allocation validation run reproduces the weighted world-level adoption estimate within the seed band.
- **Visibility**: visibility distribution of ordinary agents is heavy-tailed and capped; a head-of-state national post reaches a much larger share of awake agents in its country within two days than a community figure's post, which stays inside its region; foreign reach appears only after the translation lag and only for agents who speak the language.
- **Permissions**: a president `PolicyAction` of kind `set_interest_rate` returns `ACTION_REJECTED`; a central-bank governor's is accepted and produces the mapped `MacroPath`.
- **Human players**: a scripted session replayed after reset reproduces an identical event log; reset before a human action removes all its effects; a message to an asleep agent is delivered at the recipient's next awake hour; a possessed agent makes no autonomous decisions; `create-agent` output passes the same schema validation as generated agents; persona replies are built from a mind snapshot that contains only items the recipient was exposed to (checked with the scripted provider).
- **Notables and labels**: a notable gets a decision turn only when a trigger fires and never more than the weekly cap; with the budget exhausted notables stop acting and the report says so; every output path (CLI, transcript, report, export) labels text generated for a real person as `[simulated]`; roster validation fails if `as_of` is missing or later than the world start date.
- **Pacing**: `play` turns occur only at day boundaries; an action with a local hour when the recipient is asleep lands at the recipient's next awake bin; `--timeout` records `AUTOPILOT_TURN` and a replay of that session reproduces the identical log; possessing two agents cycles turns between them.
- **Anti-narration for free text**: a mild and an extreme phrasing of the same claim get identical engine salience; `PostPublic` triggers no per-recipient persona calls; session replay on another seed logs `ACTION_SKIPPED` instead of aborting; a world with 200 simultaneous notable triggers in one week uses at most the global ceiling of turns; `create-agent` never reallocates tables and leaves weighted aggregates unchanged.
- **Scenario sanity**: baseline has zero adoptions; awareness ≥ adoption daily; zero adoption where unavailable; adoption monotone in price/income terciles; S-shaped cumulative curve; agents asleep at release hour show no same-hour exposure.
- **Ingest** (fixture RSS/HTML, no network in CI): parsing, dedup by hash, tier attachment, classification determinism with recordings.
- **Budget**: `bench.py` 10k agents × 365 days single process: target < 60 s, hard fail > 180 s on this laptop; memory < 500 MB; per-phase ms/day printed. LLM budget test: a run with a $1 cap stops cleanly with a clear message.
- **CI**: GitHub Actions (ubuntu + windows): `uv sync`, ruff, mypy (strict on model/sim/store), pytest without `slow`/`perf`/`network`; nightly runs `slow` + `perf`.

## 11. Pre-mortem (assume it failed; causes → tripwires → mitigations)

1. **LLM cost explosion** — every chat became a call. Tripwire: budget guard trips early. Mitigation: numeric core for all exchanges; LLM only for parse/interview/render; hard USD cap per run; content-hash cache.
2. **Narration instead of emergence** — the LLM decided outcomes. Tripwire: treated results change with prompt wording but not with agent parameters; core and LLM-on runs differ in aggregates. Mitigation: LLM outputs are parameters or text, never state; all changes flow through typed events; report paired differences from the engine.
3. **Fake realism** — invented percentages. Tripwire: registry entries without source/year; `--strict` fails. Mitigation: registry + docs + marginal tests; `confidence` visible; "help wanted" list.
4. **Non-reproducible resets** — live web/LLM nondeterminism. Tripwire: determinism tests fail. Mitigation: record/replay of all fetches and LLM outputs inside the run dir; network only in `ingest`.
5. **Cascade collapse or inertia** — uncalibrated influence weights make everyone adopt in 3 days or nobody ever. Tripwire: Bass-fit p,q outside plausible ranges in the sanity test. Mitigation: bounded-confidence acceptance, belief inertia, parameter defaults locked to Bass ranges, calibration task in M2.
6. **Performance wall** — accidental per-agent Python loops. Tripwire: bench > 180 s. Mitigation: SoA + vectorized phases; perf test in CI; Rust escape hatch.
7. **Time-zone bugs** — off-by-one days around midnight/UTC. Tripwire: 02:00 UTC release test and mask-across-midnight tests. Mitigation: all timestamps UTC, local conversion only in `availability.py`, DST explicitly ignored in M1 and documented.
8. **Scope creep / no demo** — months of modelling. Mitigation: Milestone 1a demo gate before any LLM work; explicit out-of-scope list.
9. **Advisor roster outage** (process risk) — most external reviewers were down this session; mitigation: fixed-cost internal reviews + agy; user to restore accounts (see §12).
10. **Human input breaks reproducibility.** Tripwire: replaying a recorded session diverges. Mitigation: actions are events with exact sim day and hour; LLM extraction and replies are in the manifest; replay fails closed.
11. **Notables dominate or are ignored.** A president's post flips the whole world, or nobody reacts. Tripwire: share of a country aware of a head-of-state statement within 48 hours falls outside a plausible band taken from polling literature (to be sourced, `confidence: low`). Mitigation: parasocial trust priors from approval polls, partisan value alignment, bounded-confidence acceptance, word of mouth through edge trust.
12. **Real-person harm or stale rosters.** The user chose real names by default, so the LLM will write statements in the voice of real living office holders, and a roster can name someone no longer in office. Tripwire: generated text reaches a report or export without the `[simulated]` label; roster `as_of` older than the world start date. Mitigation: mandatory label enforced by a test on every output path, README disclaimer, persona grounding only on sourced public stances, dated rosters verified by web lookup when written, and the `notables.names: office` switch.
13. **Human chat and notable autonomy blow the budget.** Mitigation: per-role USD caps, a visible cost meter in `play`, notables decide only on salient days, replies cached.
14. **Multiplayer abuse, once hosted.** Spam or griefing by players. Mitigation: authentication, per-player rate limits and budgets, a moderation hook on free text; not needed for the local single-user mode.
